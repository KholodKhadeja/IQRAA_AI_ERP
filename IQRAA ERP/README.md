# 💻 IQRAA — פירוט המערכת

מסמך זה מרכז את כל המידע הטכני והתפעולי על אפליקציית **IQRAA**: ארכיטקטורה, תהליך הפיתוח, תפקידים, מסכים, התהליך העסקי, שכבת האוטומציה (n8n), זרימת הנתונים ב-Airtable ואבטחת המידע.

> לתקציר הפרויקט (מה זו IQRAA ולמה נבנתה) ראו את הקובץ הראשי: `../README.md`

> 🔗 אפליקציה חיה: https://iqraa-ai-erp-app.onrender.com

---

## 🏗️ ארכיטקטורה

המערכת בנויה משלוש שכבות:

- **Frontend ↔ Backend** — כל פעולה שדורשת אימות משתמש או כתיבת דאטה עסקי (Login, ניהול משתמשים, שיוך מנהל פרויקט, עדכוני סטטוס) עוברת דרך שירות Backend ייעודי.
- **Frontend ↔ n8n** — פעולות עסקיות מוגדרות (יצירת חשבונית, סימון תשלום) נשלחות ישירות ל-Webhook של n8n, שמבצע את הלוגיקה ורק אז כותב ל-Airtable.
- **Backend / n8n ↔ Airtable** — רק שני הרכיבים האלה מדברים עם בסיס הנתונים.

---

## 🛠️ בניית האפליקציה — Claude Code

ה-Web App כולו — כל מסך, כל קומפוננטה, כל טקסט (עברית, RTL) וכל חיבור ל-Backend/n8n — נבנה באמצעות **Claude Code**, בעבודה הדרגתית של משימה אחת, בדיקה, ואישור לפני המשך.

- **אתר רב-עמודי, ללא שלב Build** — HTML/CSS/JS טהור, קבצים סטטיים בלבד.
- **תשתית עיצוב ו-i18n מרכזית** — Design Tokens משותפים ומילון תרגום מרכזי, לשמירה על עקביות עיצובית וטקסטואלית בכל המסכים.
- **נגישות כדרישת סף** — כל מסך נבדק אוטומטית מול תקן WCAG 2.0 AA (בהתאם לתקנות הנגישות הישראליות) לפני שנחשב גמור.
- **פריסה (Deploy)** — האפליקציה והשירות ה-Backend פרוסים כשני שירותים נפרדים ב-Render.

## 🖥️ מסכים ודשבורדים עיקריים

- **👑 אדמין** — Overview עם KPI-ים עסקיים (לידים חדשים, פרויקטים פעילים, משימות באיחור, תשלומים פתוחים), שיוך מנהלי פרויקטים לפי עומס עבודה אמיתי, ניהול לידים, לקוחות, צוות וחיובים (Invoices + Payments).
- **📋 מנהל פרויקט** — Overview ורשימת פרויקטים מסוננים לפרויקטים שבאחריותו בלבד.
- **🧑‍💻 איש/אשת צוות** — משימות ופרויקטים אישיים, עם עדכון סטטוס מהיר.
- **🤝 לקוח** — מעקב התקדמות, שלב נוכחי בפרויקט, ופעולות אמיתיות של אישור / בקשת שינויים ומשוב.
- **📁 מרחב עבודה משותף לפרויקט** — הלב של המוצר: משימות, שלבי פרויקט (Pipeline), פגישות והחלטות, היסטוריית פעילות, צוות ומשאבים/קישורים חיצוניים.

## 🔄 התהליך העסקי המרכזי

זהו החלק המהותי של המערכת — השרשרת המלאה שדרכה עובר כל פרויקט, בשילוב אפליקציה ואוטומציה:

```
📝  ליד נכנס מדף הנחיתה
        │  n8n יוצר רשומת Lead ב-Airtable
        ▼
📧  מייל אישור אוטומטי + מעקב תגובה (n8n)
        ▼
📅  קביעת פגישת ייעוץ (מחוץ למערכת)
        ▼
✅  אדמין מקדם את הליד ל"ממתין לתשלום ראשון" (באפליקציה)
        ▼
🧾  יצירת חשבונית דרך מסך Billing
        │  n8n מאמת נתונים, מחשב מע"מ, ומפיק PDF
        ▼
💳  תשלום מאושר ומעודכן (n8n מסמך חשבונית ותשלום כ"שולם")
        ▼
🏢  n8n יוצר אוטומטית לקוח + פרויקט חדשים ב-Airtable
        ▼
📋  אדמין משייך מנהל פרויקט לפי עומס עבודה אמיתי
        ▼
🚀  ניהול שוטף: משימות, פגישות והחלטות, אישורי לקוח והתקדמות בשלבים
```

כל שלב שבו האפליקציה כותבת דאטה הוא כתיבה ממוקדת וזהירה (לדוגמה: קידום סטטוס ליד ל"ממתין לתשלום" בלבד) — האפליקציה אף פעם לא מדלגת שלבים או יוצרת לקוח/פרויקט בעצמה; זה תפקידה של שכבת האוטומציה, רק לאחר תשלום מאומת בפועל.

## 🗄️ Airtable — מקור האמת וזרימת נתונים

Airtable הוא בסיס הנתונים היחיד של המערכת (Users, Leads, Clients, Projects, Tasks, Payments, Invoices). חלק מה-Workflows מבצעים **מעבר נתונים אמיתי בין טבלאות** — למשל, ה-Workflow "New Client + New Project" קורא ליד במצב "שולם תשלום ראשון" מטבלת **Leads**, יוצר ממנו רשומה חדשה בטבלת **Clients**, יוצר על בסיסה רשומת **Project** חדשה, וכותב חזרה לרשומת ה-Lead המקורית שהתהליך הושלם — תנועת מידע מלאה בין ארבע טבלאות, ללא מעורבות של האפליקציה.

הפרונט-אנד עצמו אף פעם לא ניגש ל-Airtable ישירות — כל תנועת מידע בין טבלאות מתבצעת בצד השרת (Backend או n8n) בלבד.

## 🔐 אבטחה והרשאות

- כניסה למערכת (Login) מאומתת מול Airtable דרך שירות Backend ייעודי, עם session מאובטח (עוגיית httpOnly).
- כל תפקיד מוגבל בפועל למידע שלו — הן בממשק והן בבקשות לשרת, ולא רק בהסתרת כפתור.
- אף פעולה רגישה (כתיבת דאטה עסקי) לא מתבצעת ישירות מהדפדפן מול Airtable.
